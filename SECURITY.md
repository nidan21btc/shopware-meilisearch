## Reporting a vulnerability

Please do not post vulnerability details in a public issue, discussion or pull
request. Once private vulnerability reporting has been enabled on the public
repository, open **Security → Advisories → Report a vulnerability** and submit a
private report to the maintainers through GitHub.

Include the affected version, a description, impact and reproducible steps using
synthetic data. Do not include passwords, API keys, customer data, real search
terms, raw HAR files or private shop exports. Wait for a maintainer's response
before sharing sensitive details publicly. There is no guaranteed response time,
resolution or ongoing security maintenance.

The feature is managed through GitHub repository settings and is available for
public repositories. Its availability and notification delivery depend on GitHub
and repository settings; check that the reporting button is enabled after making
the repository public. See GitHub's [private vulnerability reporting guide](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

The [security documentation](docs/security.md) describes the implemented controls,
known exposure and operating limits. A private reporting channel does not change
those limits or establish a support commitment.
